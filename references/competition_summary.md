# 比赛总结模板（Competition Summary）

> TJU-Official-Document-Writing-Skill ｜ references 高校模板库 4/6
> 与 tju-extension §2（科研总结）、`project_closing_report.md`（结题报告）的分工：本模板面向**竞赛项目**赛后总结，重"赛题应对与团队复盘"；需要报送主办方的结题材料请用结题报告模板。

## 使用场景

- 学科竞赛（电子设计、FPGA 创新、数学建模、挑战杯等）结束后提交学校的总结材料；
- 团队内部复盘会底稿；下一届传帮带的经验文档。

## 推荐结构

```
一、赛题与备赛概况（300 字）
    赛项名称/级别/周期/团队分工；赛题要求一句话概括 + 关键约束指标
二、方案与实现（600-1000 字，全文重心）
    总体架构 → 关键技术选型及理由 → 本人/本组负责模块的实现要点
    关键指标实测对照表（我方成绩 vs 赛题要求）
三、比赛过程复盘（300-500 字）
    现场时间线关键节点；突发问题与现场处置（1-2 个典型）
四、成绩与不足（200-300 字）
    名次/奖项 + 差距归因（对失分项逐条归因，不回避）
五、经验与建议（200-400 字）
    可复用的方法（工具链/分工模式/时间管理）；对下届参赛的具体建议
```

## 禁止事项

- 禁止只报喜不报忧：失分项与备赛失误必须如实归因；
- 禁止技术细节失真——指标数据必须与实测记录一致，不得凭记忆填写；
- 禁止省略团队分工把集体成果写成个人英雄史；
- 禁止泄露涉密赛题内容或违反赛项保密条款；
- 禁止把"没有获奖"的比赛写成流水账了事——备赛方法论的提炼同样有价值。

## 示例（复盘小节）

> 现场测试环节出现了一次渲染力突变：预赛区稳定的渲染引擎在评测工位上复现了偶发抖动。排查发现是评测平台供电电压低于实验室 0.3 V，导致 DAC 参考电压漂移。我们十分钟内完成了限幅参数的在线整定并通过复测。教训：赛前应针对供电容差做边界测试，现场工具箱需常备参数整定的上位机脚本——这条已写入下一届的备赛清单。
